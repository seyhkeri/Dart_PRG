# Лабораторная работа №7. Углублённое ООП в Dart - RPG-битва

Консольная пошаговая текстовая игра в жанре RPG, разработанная на языке Dart. Проект демонстрирует практическое применение ключевых концепций объектно-ориентированного программирования: наследования, абстракции, инкапсуляции и полиморфизма.

## Запуск
1. Клонировать репозиторий:  
   git clone <URL_вашего_репозитория>
2. Перейти в папку проекта:  
   cd lab_rpg_fio
3. Установить зависимости:  
   dart pub get
4. Запустить проект:  
   dart run

## Что изучили
**Создание абстрактных классов и методов** для формирования жестких программных контрактов, обязывающих дочерние классы реализовывать специфичную логику.
 **Использование ключевого слова `extends`** для наследования полей и методов базового класса, что позволяет избежать дублирования общего кода.
 **Переопределение методов (`@override`)** и полиморфное поведение функций, обрабатывающих разные объекты через интерфейс единого базового предка.
 **Работу с конструкторами и списками инициализации (initializer list)**, а также вызов родительских конструкторов через super.

## Ответы на вопросы

### 1. Что такое абстрактный класс? Почему нельзя написать Character() напрямую?
**Абстрактный класс** - это специальный базовый класс-шаблон, предназначенный исключительно для наследования, который нельзя инстанцировать (создать объект на его основе). 
Написать Character() напрямую нельзя, потому что данный класс описывает абстрактную сущность «Персонаж». У него нет конкретной реализации игровых механик (например, метода attack()). Объект должен обладать конкретной логикой и типом, таким как Воин (Warrior), Маг (Mage) или Лучник (Archer).

### 2. Зачем нужен super в конструкторе наследника? Что будет если его убрать?
Ключевое слово super используется для вызова конструктора родительского класса (Character) и передачи ему обязательных параметров (таких как name и hp), необходимых для инициализации базовых полей. 
Если убрать super, код не скомпилируется. Dart выдаст ошибку, так как родительский класс не имеет конструктора по умолчанию (без параметров), и компилятор не сможет автоматически создать базовую структуру персонажа.

### 3. В чём разница между @override у attack() в Warrior и takeDamage() в Warrior? Почему второй переопределяет метод который уже имеет реализацию в родителе?
**attack()** реализует абсолютно «пустой» (абстрактный) метод родителя. Это обязательное выполнение контракта, без которого класс Warrior не смог бы существовать.
 **takeDamage()** переопределяет метод, который уже имеет готовую базовую логику в классе Character. 
Воин переопределяет его для того, чтобы модифицировать стандартное поведение - внедрить механику брони (armor), которая поглощает часть урона перед тем, как окончательно вычесть единицы здоровья через вызов super.takeDamage(reduced).

### 4. Функция fight(Character a, Character b) не знает кто реально придёт — Warrior, Mage или Archer. Как называется эта концепция и где вы её уже видели во Flutter?
Эта концепция называется полиморфизмом. Она позволяет взаимодействовать с объектами различных типов через единый интерфейс их общего предка. 
Во Flutter эта концепция встречается повсеместно при работе с виджетами. Например, метод Widget build(BuildContext context) принимает и возвращает тип Widget, однако внутри него мы можем возвращать любых его наследников: Text, Column, Container или ElevatedButton.

### 5. Что означает _random с нижним подчёркиванием в классе Character?
Нижнее подчёркивание перед именем члена класса (_random) означает инкапсуляцию (приватность) на уровне библиотеки (файла). Это свойство делает объект генератора случайных чисел скрытым от внешнего кода и доступным для использования только внутри самого класса Character.
